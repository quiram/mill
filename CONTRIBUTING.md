# Contributing to mill

This document is for people working on mill itself. If you just want to use it, see the [README](README.md).

## Repo layout

```
apm.yml                                   # package manifest + marketplace block (single source of truth, incl. version)
.claude-plugin/marketplace.json           # generated by `apm pack` — committed, consumed by APM & Claude Code
.claude/skills/release/SKILL.md           # repo-local release skill (not part of the package)
assets/logo.svg                           # the windmill
docs/                                     # mill's own AI context, indexed by AGENTS.md
skills/
  start-task/SKILL.md
  recommend-model/SKILL.md
```

## Design decisions

### Defaults are always confirmed

Skills read the host project's context, and when it is silent they fall back to a stated default. The rule that makes this safe is that a default is never acted on silently: the skill says what the context lacked, proposes the default, and waits. Keep this when adding skills; it is what makes mill usable in projects that have never heard of it.

### Model recommendation is its own skill, fed by a brief

Judging difficulty needs the task, and `start-task` is where the task is read. But the judgement itself is reusable, and tangling it into `start-task` would make it unusable on its own. So `recommend-model` takes a **brief** as input rather than fetching anything itself: `start-task` reads the ticket and skims the code, then passes both along. `start-task` treats the recommendation as advisory and carries on if the skill is unavailable.

Recommendations are expressed in vendor-neutral tiers and mapped to the models the user can actually select, so no skill hard-codes a model lineup.

### No setup skill

mill has no prerequisites to install: no tooling, models or OS permissions. Everything it needs it discovers from the project's context at run time or asks the user for, so there is nothing for a setup skill to prepare.

## Releasing

Releasing is handled by the repo-local `release` skill: with a coding agent, ask it to "release version X.Y.Z". The skill lives at [.claude/skills/release/SKILL.md](.claude/skills/release/SKILL.md) — it is not part of the mill package — and doubles as the manual step-by-step instructions.
