# Task tracking

Work on mill is tracked as **GitHub Issues on [quiram/mill](https://github.com/quiram/mill/issues)**.

## Reaching it

Use whatever access to GitHub the current environment offers — the `gh` CLI, a GitHub MCP server, or the REST API with a token. They are equivalent for reading and writing issues, so pick what is available and working.

Confirm access before relying on it, and probe read-only: list or read an existing issue, never create a test one.

## Ticket conventions

Lead with the business goal, dedupe against existing issues, and keep to one goal per ticket.
